# Phase 0 - 设备矩阵与测量协议

## 1. 目标
- 为后续启动、滚动、阅读器翻页、RN 首开、构建与包体积基线建立统一采集方式。
- 确保不同阶段的数据具备可复现性和可比较性。

## 2. 设备矩阵

### 最低要求
| 档位 | 数量 | Android 版本 | 目的 |
| --- | --- | --- | --- |
| 低端机 | 1 | 至少覆盖主流低版本之一 | 验证内存、启动、翻页、WebView、弱网体验 |
| 中端机 | 1 | 至少覆盖主流中间版本之一 | 作为主要日常基线设备 |
| 高端机 | 1 | 至少覆盖当前主流高版本之一 | 验证高刷、动画、RN 首开、Benchmark 差异 |

### 系统版本覆盖
- 至少覆盖 `2` 个 Android 主版本。
- 若实际设备不足，允许使用真机 + 模拟器组合，但性能基线优先使用真机。

## 3. 网络环境
| 环境 | 用途 |
| --- | --- |
| 正常网络 | 默认基线采集 |
| 弱网络 | 验证登录、搜索、福利 WebView、Bridge 拉数、缓存兜底 |
| 离线 | 验证缓存、错误态、阅读器与福利页降级路径 |

## 4. 测量轮次
| 指标 | 轮次 | 说明 |
| --- | --- | --- |
| 冷启动 | 5 次 | 去掉异常值后记录中位数与范围 |
| 首页滚动 | 3 次 | 记录帧时间和主观卡顿说明 |
| 阅读器翻页 | 3 次 | 记录翻页耗时、卡顿、内存变化 |
| RN 页面首开 | 3 次 | 设置/书架/分类/我的至少选 2 个代表页 |
| 构建时长 | 3 次 | 分冷构建与增量构建 |

## 5. 记录模板
每次采集都必须记录以下字段：
- 采集日期
- Git 提交号
- 设备型号
- Android 版本
- 构建类型
- 网络环境
- 轮次
- 指标值
- 是否有异常说明

## 6. 指标定义
| 指标 | 说明 |
| --- | --- |
| 冷启动 | 从应用启动到首个可交互主界面稳定显示 |
| 首帧 | 从启动到首帧绘制完成 |
| 首页滚动 | 首页滚动过程中的帧表现和明显卡顿情况 |
| 阅读器翻页 | 阅读器翻页、切章、设置变更的流畅度与耗时 |
| RN 首开 | RN Host 页面首次进入到页面稳定可交互 |
| AAB/APK 体积 | 构建产物大小 |
| 构建时长 | 冷构建和增量构建耗时 |
| 内存峰值 | 关键路径运行期间的内存峰值 |

## 7. 当前约束
- 当前仓库环境尚未绑定固定设备清单，因此真机指标暂列为待补采。
- 在未补齐真机数据前，Phase 0 只能把“协议、模板、仓库内静态基线”标记为就绪，不能宣称性能基线闭环。

## 8. 执行说明
- Phase 0 先落地模板与静态基线。
- 待具备真机或稳定模拟器环境后，再补充启动、滚动、翻页、RN 首开等动态指标。
