# Phase 0 - 基线与控制面板

## 目标
- 建立可测量、可比较、可回滚的基线与控制面板。
- 为 `Phase 1` 和 `Phase 2` 提供唯一可信的进入判断依据。
- 输出后续重构必须遵守的禁区清单、测试数据方案和 kill switch 最小方案。

## 范围
- 核心用户路径矩阵。
- Route / Bridge / Storage / Config / Schema 资产盘点。
- 构建、体积、性能、测试现状基线。
- 设备矩阵与测量协议。
- 风险图谱与禁区清单。
- 稳定测试数据方案设计。
- Feature flag / kill switch 最小方案设计。

## 非目标
- 不修改业务功能语义。
- 不修改 UI 设计和交互风格。
- 不进行发布配置、安全配置或数据库策略的正式改造。
- 不在本阶段直接推进模块拆分和大规模代码重写。

## 进入条件
- 仓库可正常读取。
- Android 构建配置已可分析。
- `docs/refactor/` 文档骨架已创建。
- 当前工作树可支持原子提交。

## 硬阈值
- 核心路径覆盖率必须达到 `100%`。
- 资产清单核心对象覆盖率必须达到 `100%`。
- 至少完成一轮可复现基线采集。
- 每项基线必须记录设备、系统、网络、构建类型、采集时间。
- 风险必须按 `blocker/high/medium/low` 分级。

## 风险与回滚
- 风险：
  - 核心路径漏项导致后续验证失真。
  - 指标采集环境不一致导致基线失去可比性。
  - 测试数据方案缺失导致 Phase 2 自动化不稳定。
  - 未提前定义 kill switch 导致后续大改不可逆。
- 回滚：
  - 本阶段以文档与盘点为主，若结论不稳定则回滚到上一个文档提交。
  - 任何无法证实的结论不得进入下一阶段，必须保留为 `high` 或 `blocker` 风险。

## 退出条件
- 全部 `V0-*` 至少为 `green`。
- 不存在 blocker 级未知项。
- 若存在 high 级遗留，必须写入 `decision-log.md` 且不得影响 `Phase 1` 进入判断。
